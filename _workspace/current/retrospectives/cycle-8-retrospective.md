## 이 사이클이 가르친 것

### 1. 논쟁은 테스트를 낳고 합의는 낳지 않는다

변이 스윕이 무방비 3건을 찾았다. **전부 만장일치 결정**이었다.

| 결정 | 성격 | 최초 방어 |
|---|---|---|
| D-2 티어 삭제 | 디렉터 판정, 대안 기각 기록 | 있음 |
| D-4 아이콘 크기 | QA가 스펙 기각, 재계산 | 있음 |
| D-10 담김 불변조건 | QA 3건 추가 신고 | 있음 |
| D-3 터치 기하 | 네 역할 독립 동의 | **없음** |
| D-7 배지 | 중재 결과, 양측 합의 | **없음** |
| D-8 레일 3개 동결 | 디자이너 제약, 이견 없음 | **없음** |

논쟁이 있으면 누군가 근거를 적어야 하고, 그 근거가 단언이 된다. 모두가
동의하면 적을 것이 없어 보인다. **회의록에서 가장 매끄럽게 지나간 항목이
코드에서 가장 취약한 항목이다.**

cycle-7이 "변이 스윕은 커버리지 측정이 아니라 무방비 지점 탐지기"라고 적었다.
이번 사이클은 그 탐지기가 **어디를 먼저 봐야 하는지**를 알려준다: 이견 없이
통과한 결정.

### 2. 실척을 고르면 답이 바뀐다 — 그리고 하한이 없으면 모두가 고른다

같은 92u 버튼에 대해 한 회의가 두 판정을 냈다:

```
D-3  강하 92u 유지   1280 CSS로 측정 → 100.1px → PASS
D-4  레일 92u 기각    501 CSS로 측정 →  39.2px → FAIL
```

최선 실척으로 기존을 재고, 최악 실척으로 신규를 쟀다. 게다가 D-4가 "501이
진짜 최악"이라 적은 것도 **틀렸다** — fill 밴드 최악은 0.3598(280×653)이고,
채택한 103.3u는 D-4가 주장한 "모든 구성 PASS"를 달성하지 못한다.

근본 원인은 숫자가 아니라 **지원 하한이 문서 어디에도 없었다**는 것이다.
하한이 없으면 모든 결정이 자기에게 편한 실척을 정당하게 고를 수 있다.

**일반화**: 임계값을 논하기 전에 그 임계값을 재는 조건을 먼저 명명하라.
조건이 없는 임계값은 임계값이 아니라 수사(修辭)다. D-11이 375×667로 명명했다.

cycle-7이 "근사로 결정의 근거를 적는 것은 틀리다"를 배웠다. 이번은 한 단계
위다 — **정확한 측정도 조건을 명명하지 않으면 근거가 되지 못한다.**

### 3. 커버리지 아티팩트가 거짓말하면 그것이 최악의 거짓말이다

부채 표가 2사이클간 **도달 불가 컨트롤을 감사됨으로 계상**했다. 구 배치는
SANCTUM을 y−708에 주차했을 뿐 비활성화하지 않았고, 감사는 `activeInHierarchy`로
거른다. 성소 탭 4개와 성장 "+" 3개가 아무도 누를 수 없는 동안 표에 있었다.

11개 항목은 이번 사이클에 **바뀌지 않았다. 그 항목들의 참이 바뀌었다.**

부채 표의 존재 이유는 "커버리지에 대해 믿을 수 있는 아티팩트"다. 거기에
실패 모드가 살면 그것을 검사할 상위 아티팩트가 없다. cycle-8을 diff하는
독자는 동일한 표를 보고 아무 일도 없었다고 결론지을 것이므로 독스트링에 적었다.

### 4. 제보의 형태가 결함의 크기를 숨긴다

사용자는 "로비가 다 활성화되어 있다"는 **UI 선호**로 보고했다. 실제로는:

```
배포 빌드 E_w = 1176 고정 (템플릿이 1280:853 잠금)
SideBySideFloor = 1248  →  1176 < 1248  →  모든 플레이어 항상 stacked
1604u 열 vs 783.7u 캔버스, 루트 ScrollRect 없음
  SORTIE 100%  SANCTUM 13.5%  MAP 0%
  성소 지출 UI 0%  (가시 75.7u < TabContent 오프셋 116u)
```

**배포 빌드에 영구 강화 경제가 있고 구매 버튼 도달률이 0이었다.** 상단바
유물 카운터는 100% 가시였다 — 잔고는 늘 보이고 문은 없었다.

사용자가 본 "다 활성화" 화면은 **에디터 Game 뷰**였다(스크린샷 1868×998 →
E=1313 ≥ 1248). 플레이어가 실제로 받는 화면을 사용자는 보고할 수 없었다.

**일반화**: 제보가 선호의 언어로 도착해도 재분류를 시도하라. 사용자는 자기가
보는 프레임만 보고할 수 있고, 그 프레임이 플레이어의 프레임이 아닐 수 있다.

### 5. 이름이 거짓말하는 테스트는 없는 테스트보다 나쁘다 — 4번째 사례

`CampaignMapActions_AreReachableAndClearTheTouchFloor`가 MAP 가시율 0%인 동안
초록이었다. `interactable`과 rect 크기만 봤기 때문이다.

그리고 이 사이클이 그 함정을 **다시 놓을 뻔했다**: MAP 버튼을 "전체 지도"로
개명하자 `FindButton("지도")`가 레일 아이콘을 반환하게 됐다. 둘 다 활성이고
둘 다 44px를 넘으므로 테스트는 초록인 채 **완전히 다른 컨트롤을 잰다**.
ContainmentTests가 자기 파일에 `FindButton`을 복사하지 않기로 하면서 잡았다.

**접두사 조회는 이름이 유일할 때만 조회다.** 이름이 아니라 `GameObject.name`
같은 안정적 식별자로 찾아야 하고, 라벨은 별도 줄에서 단언해야 한다.

### 6. 해석으로 못 얻는 답은 화면이 준다 — §4c가 또 맞았다

게이트 초안은 "워든이 열린 653u 안에 보이는지"를 `[NOT MEASURED]`로 열어뒀다.
정직한 판단이었다: 디오라마 앵커는 `ViewWorld.ToWorld()` 3D 월드 좌표이고
화면 x는 카메라 투영에 달렸으므로 캔버스 u와 비교할 수 없다.

인터뷰 스펙은 그 둘을 혼동한 채 "레일 x=[16,106.2]은 앵커 x=540보다 왼쪽이라
아무것도 가리지 않는다"고 **단정**했다. 결론은 맞았지만 근거는 성립하지
않았다 — 두 좌표계를 뺄셈한 것이다.

빌드하고 열었더니 답이 나왔다. 653u 안에 워든과 보스가 보인다.

**일반화**: 미측정을 미측정으로 적는 것은 옳다. 하지만 거기서 멈추지 마라 —
§4c는 뷰 레인에 대해 화면을 열라고 이미 요구하고 있고, 이번엔 그 요구가
해석으로 도달 불가능한 질문 하나를 정확히 겨눴다. cycle-3은 EditMode 319/319
초록에서 화면을 열어 7건을 더 찾았다. 이번엔 0건이었지만, **0건임을 아는
것도 화면을 열어야 얻는다.**

### 7. 사용자 반복이 측정과 같은 결론에 도달했다 (D-12)

게이트 판정 후 사용자가 로비를 직접 구동하고 지시 4건을 순차로 냈다. 그
궤적이 그대로 설계 탐색이었다:

| # | 지시 | 우리가 만든 것 | 실측 결과 |
|---|---|---|---|
| 1 | "닫기 버튼도 있었으면" | 레일 하단 닫기 타일 103.3u | 플로어 PASS, D-8 충돌 |
| 2 | "처음엔 항상 닫혀 있어야" | 기본값 = 닫힘 | AC-5 전제 소멸로 비용 0 |
| 3 | "X는 우상단에, 재클릭도 둘 다" | 패널 X 56u + 재클릭 | X = **24.5px, 미달** |
| 4 | "X는 빼고 재클릭만" | 재클릭 단독 | 신규 컨트롤 0, 부채 0 |

3번을 구현하는 도중 X가 24.5 CSS px로 측정됐다 — §4d 기준으로 신규 미달
컨트롤은 결함이다. 플로어를 넘기려면 103.3u가 필요하고 그건 성소 폭의 1/4을
헤더에 박는 것이다. 보고서를 쓰기 전에 4번 지시가 도착해 그 부채를 애초에
만들지 않고 닫혔다.

**일반화**: 사용자 반복을 "요구사항이 흔들린다"로 읽으면 각 단계를 그대로
구현하고 끝난다. 설계 탐색으로 읽으면 각 단계를 **측정**하게 되고, 측정이
다음 반복과 같은 방향을 가리키는지 볼 수 있다. 이번엔 가리켰다 — 사용자가
X를 뺀 이유와 우리가 X를 뺐어야 할 이유가 같았다.

반대 경우도 대비해야 한다: 측정이 사용자와 다른 방향을 가리키면 그때는
**숫자를 들고 말해야** 한다. 조용히 구현하고 부채로 적는 것은 D-11이 회의에
대해 지적한 것과 같은 실패다.
