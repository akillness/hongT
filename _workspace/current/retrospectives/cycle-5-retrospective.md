## 8. 테스트 레인이 내 주석의 오류를 잡았다

`GuidanceCatalog`에 "ceiling is 32"라고 쓰고 가드를 `bit < 32`로 썼다.
테스터가 T1에서 **천장을 직접 계산해** `Count <= 31`을 주장했다 — 근거는
`ExtractInt`가 digit만 읽으므로 sign bit가 서면 음수 직렬화 → 0으로 되읽기.

그런데 같은 파일 T2에서는 `MarkSeen(31)` **is True**로 "bit 31 is legal"을
어서션했다. **두 주장이 모순이었다.**

내가 `BitCeiling = 31`을 넣자 T2가 빨개졌고, 그게 신호였다. 라운드트립을
시뮬레이션해 판정:

```
bit 30 -> "1073741824"  -> read 1073741824   ok
bit 31 -> "-2147483648" -> read          0   DATA LOSS
```

**T1 사유가 맞고 T2 어서션이 틀렸다.** 조치는 상수화 + T2 수정 + **이유를
어서션으로**: 최상위 legal 비트를 실제로 Save→Load 왕복시켜 보존을 확인한다.

테스터의 자기 진단이 정확했다: *"같은 파일에서 두 어서션을 서로 다른 출처로
썼다. T1은 파서 동작에서 역산했고 T2는 가드를 문자 그대로 읽었다. 둘을 한
번도 마주 세우지 않았다."*

**교훈**: 상한을 서술하는 주석을 달았으면 **그 상한을 검사하는 어서션이 같은
계산을 돌려야 한다.** 그러면 두 주장이 출처를 공유해서 갈라질 수가 없다.

이건 §7의 내 실수와 같은 뿌리다 — 둘 다 **두 개의 정보원을 마주 세우지 않은
것**이다. 나는 파일과 내 기억을, 테스터는 파서와 가드를.

### 9번 — 필드는 맞고 렌더만 틀렸다

`Image.Type.Filled`인데 `sprite`가 null이면 uGUI는 `type`·`fillAmount`를
**아예 읽지 않고** 풀 렉트를 그린다. `Sync()`는 매 프레임 정확한 값을 썼고
아무도 읽지 않았다. 체력·기름·경험치·보스HP·추출·쿨다운 — 전부.

이 결함의 성격이 특이하다: **모든 자동 검사가 통과한다.** EditMode에서
`fillAmount`를 읽으면 정확한 값이 나오고, rect 감사는 크기와 겹침만 본다.
"그 값이 화면에 반영되는가"가 **어느 테스트의 정의역에도 없다.**

### 10번 — 내 주석이 내 실수를 적어놨다

`SetAbandonAvailable(_state == State.Dungeon)`에 이렇게 썼다:

> 프롤로그는 3웨이브면 스스로 끝나고 시련은 60초 시계라 둘 다 아무도 못 가둔다

**이기는 경로에만 참이다.** 죽으면 재강하 루프고, `캠페인으로`는
`EnableCampaignUi`가 붙이는데 프롤로그는 그 메서드를 호출하지 않아 **버튼이
생성조차 안 됐다.**
