## 1. 적용 범위 — 강하(던전) 전용 `[확정 D-22]`

W4는 `_dungeon` 게이트 뒤에만 산다. 프롤로그·시련·아레나 무접촉.

조사 중 로비 진입점 4개를 심 직접 구동으로 측정했다 `[MEASURED]`:

| 진입점 | GameMode | 적 | 기믹 | 강화 | 스킬 | 판정 |
|---|---|---:|---:|---|---|---|
| 출정(스테이지 9) | `Dungeon` | 웨이브 | 2~4 | ✓ | ✓ | **채택** |
| 점화 훈련 | `Prologue` | 4 | 0 | ✗ | **✗ 봉인** | 제외 |
| ○○ 시련 5종 | `Training` | **0** | 2~4 | ✓ | ✓ | 제외 |
| 아레나 | `Arena` | 무한 | 0 | ✗ | ✓ | 제외 |

### 프롤로그가 후보였고 왜 탈락했는가

프롤로그 wave 1이 **이 문서가 분화시키려는 적 4종을 정확히 한 마리씩** 뱉는다:

```
wave 1: Scout, Shade, Possessed, EmberCohort   (각 1마리, HP 전부 58.0)
```

튜토리얼이 *"적이 네 종류다"* 를 가르치려 그렇게 짜인 것이다. W4를 여기 얹으면
**신규 콘텐츠 0으로** 그 소개가 참이 됐을 것이다.

**탈락 사유: 프롤로그는 스킬이 봉인이다** (`CinderSim.cs:1193`):

```
// §1: the prologue is movement + basic attack only — every skill key,
//     the dash included, is ignored.
if (_prologue) { return; }
```

실측 대조 — 프롤로그 Nova·Ward 미발동(기름 100→100), 아레나 발동(100→61→31),
던전 발동(100→55→25).

→ **Possessed의 −6 기름 흡수가 프롤로그에서 아무 일도 하지 않는다.** 쓸 수 없는
자원을 뺏는 것은 손실이 아니고, 손실이 없으면 *"얘를 방치하면 스킬을 못 쓴다"*
는 우선순위 판단(§4.4)이 생기지 않는다. 4종 중 3종만 유효했을 것이다.

사용자가 프롤로그 제외를 지시(2026-08-09), 디렉터가 D-22로 확정.

### 이 결정이 남기는 부채

**튜토리얼은 계속 4종을 소개하면서 그 넷이 기계적으로 동일하다는 것도 가르친다.**
플레이어는 프롤로그에서 "네 종류가 있지만 다 같다"를 배우고 던전에서 그것이
뒤집힌다. **W4가 성공할수록 이 역전이 커진다.**

| 부채 | 만료 | 해소 조건 |
|---|---|---|
| 튜토리얼이 4종 동일성을 가르침 | W4 착지 후 다음 사이클 | 프롤로그 §1 계약 재협상 + Possessed 대체축 |

## 2. "확률"을 무RNG로 — 선례 재사용

`LootGradeSpec`(AMENDMENT #14)이 이미 답을 갖고 있다:

```
Roll(enemyId, wave, dropOrdinal) → 0..99      정수 어밸런치, 부동소수점 0
Resolve(roll, finePity, epicPity)             임계값 + 천장
Advance(granted, ref finePity, ref epicPity)  단조 카운터
```

구현 확인: `DungeonProgressionSpec.cs:406` `public static int Roll(int enemyId,
int wave, int dropOrdinal)`.

W4는 **같은 형태를 다른 축에** 쓴다:

```
SkillRoll(enemyId, wave, attackOrdinal) → 0..99
발동 = roll >= ThresholdFor(archetype)  OR  pity >= PityLimitFor(archetype)
```

- 런타임 난수 **0개**. 같은 입력 → 같은 결과.
- 해시 입력이 **전부 플레이어에게 보이는 값**이다(cycle-3 S5: 불가시 게이지
  금지). `enemyId`는 스폰 순서, `wave`는 HUD, `attackOrdinal`은 셀 수 있다.
- 천장은 "연속 미발동이 N회를 넘지 않는다"는 **공정성 보장**이지 주 경로가
  아니다(§5 실측).

## 3. 두 층으로 나눈다

| 층 | 성격 | 언제 | 확률 |
|---|---|---|---|
| **기질(temperament)** | 상수. 그 아키타입은 항상 그렇다 | 상시 | 없음 |
| **스킬(skill)** | 굴림. 가끔 나온다 | 공격 시 | 해시 |

기질만 있으면 "다르긴 한데 밋밋"하고, 스킬만 있으면 "평소엔 똑같은데 가끔
튄다"가 된다. **둘 다 있어야 4종이 실제로 다른 적이 된다.**

## 4. 아키타입 4종

속성이 이미 넷을 가르고 있으므로(`HackTypes.cs:1034` `ElementOf`) **행동이
속성을 배신하지 않게** 설계한다 — 제약 5(§6).

### 4.1 EmberCohort — Ember(불) · 「달려드는 것」

| 층 | 내용 |
|---|---|
| 기질 | **넉백 저항 ×0.75** — 밀어도 덜 밀린다. 접근 속도 ×1.10 |
| 스킬 | **가속** — 발동 시 3초간 이동속도 ×1.35 |
| 플레이어가 배우는 것 | *"얘는 겨냥해도 잘 안 날아간다. 거리를 먼저 벌려라"* |

불 = 확산·압박. **W1의 반례로 존재한다** — 겨냥 넉백이 만능이 아님을
가르치는 적이다.

### 4.2 Scout — Frost(얼음) · 「거리를 지키는 것」

| 층 | 내용 |
|---|---|
| 기질 | **넉백 저항 ×1.40**(잘 날아간다). 사거리 밖 대기 링 반경 ×1.20 |
| 스킬 | **후퇴 스텝** — 플레이어 반대 방향 짧은 이동, 다음 공격 쿨 ×0.85 |
| 플레이어가 배우는 것 | *"얘는 잘 날아간다. 벽·분출구로 보내기 가장 좋은 표적"* |

얼음 = 고정·거리. **W1의 최적 표적**이다. 넉백 저항이 가장 높으므로 겨냥
넉백의 교보재가 된다.

### 4.3 Shade — Veil(장막) · 「박자를 끊는 것」

| 층 | 내용 |
|---|---|
| 기질 | 넉백 저항 ×1.00(기준). 접근 중 **불규칙 정지**(주기 미확정 — §9) |
| 스킬 | **지연 타격** — 접촉 프레임 2 → 3(한 프레임 늦게 때린다) |
| 플레이어가 배우는 것 | *"얘의 스윙은 내 예측보다 늦게 온다. 회피 타이밍이 다르다"* |

장막 = 기만. **예고를 추가하지 않으면서** 읽기를 어렵게 만드는 유일한 축이다
— 접촉 프레임은 이미 보스 프로파일이 쓰는 축이다(`contactFrame: {3,2,1}`).

### 4.4 Possessed — Void(공허) · 「빼앗는 것」

| 층 | 내용 |
|---|---|
| 기질 | 넉백 저항 ×1.00. 사거리 ×0.95(더 붙어야 때린다) |
| 스킬 | **기름 흡수** — 타격 성공 시 플레이어 기름 −6, 피해는 그대로 |
| 플레이어가 배우는 것 | *"얘를 방치하면 스킬을 못 쓴다. 우선순위가 높다"* |

공허 = 흡수·부정. **피해가 아니라 자원**을 건드리므로 S3 노출 곡선과 무관하다
(§6 제약 2). 기름은 이미 제단·픽업·처치가 주는 자원이라 신규 통화가 아니다.

**경제 서명 완료** — 협상록 entry 19. −6 확정. 제단 +18의 3회 흡수 = 제단 1회
무효화가 의도된 크기다.

## 5. 수치 `[MEASURED — 시뮬 2,160 표본]`

웨이브 1–9 × 적 id 1–20 × 공격 12회로 해시 분포와 천장 동작을 검증했다.

| archetype | element | 임계 | 천장 | 발동률 | 천장 기여 | 최장 무발동 |
|---|---|---:|---:|---:|---:|---:|
| EmberCohort | Ember | 78 | 6 | 24.8% | 11.0% | 6 |
| Scout | Frost | 72 | 5 | 30.7% | 10.1% | 5 |
| Shade | Veil | 82 | 8 | 20.6% | 10.1% | 8 |
| Possessed | Void | 85 | 9 | 17.4% | 11.7% | 9 |

**판독**

- 실측 발동률이 기대치(100−임계)에 근접 → 해시 균등성 확인.
- 천장 기여가 전부 **≤12%** → 천장이 보험이지 주 경로가 아니다.
  초안은 천장을 6으로 통일했는데 Possessed에서 **23%**가 나왔다 — 임계가
  높을수록 천장이 자주 걸리므로 **아키타입별로 다르게** 잡았다.
- 최장 무발동이 정확히 천장값 → 천장이 실제로 작동한다.

**발동률 서열이 성격과 맞는다**: Scout가 가장 자주(30.7%) 후퇴하고,
Possessed가 가장 드물게(17.4%) 빨아먹는다 — 자주 나오면 짜증나는 스킬일수록
드물게 나온다.

## 7. W1과의 결합 — 이 설계의 진짜 목적

넉백 저항을 아키타입별로 다르게 준 것이 핵심이다:

| archetype | 넉백 저항 | W1 겨냥 시 |
|---|---:|---|
| Scout | ×1.40 | **가장 잘 날아간다** — 벽·분출구로 보내기 최적 |
| Shade / Possessed | ×1.00 | 기준 |
| EmberCohort | ×0.75 | **잘 안 날아간다** — 겨냥이 안 통하는 적 |

**W4는 W1에 결을 준다.** 겨냥 넉백이 모든 적에게 똑같이 통하면 그것은 도구가
아니라 버튼이다. 어떤 적은 날아가고 어떤 적은 버티면, "누구를 어디로 보낼
것인가"가 매 순간의 판단이 된다.

역으로 **W1이 없으면 W4의 넉백 저항 축은 죽는다** — 밀 방향을 못 고르는데
저항 차이를 알 방법이 없다. 두 수가 서로를 필요로 한다.

W1의 뼈대는 이미 있다 — `CinderSim.ResolveFinisherVariant`가 입력 방향으로
변종을 가른다 `[MEASURED]`:

```
정면 입력 → Launcher  넉백 ×1.60
뒤   입력 → Retreat   넉백 ×0.70
상하 입력 → Spin      넉백 ×1.00
무입력    → Neutral   넉백 ×1.00
```

`CinderSim.cs:2496`이 이것을 `_dungeon` 뒤에 둔다 — W4와 같은 게이트다.

## 8. 심 계약 (programmer 검토 필요)

```
DungeonProgressionSpec.cs 에 추가 (선례: BossVarietySpec)
  EnemyArchetypeProfile { KnockbackResist, SpeedMul, RangeMul,
                          ContactFrameDelta, SkillThreshold, SkillPityLimit }
  Table[] indexed by (int)EnemyVisual
  SkillRoll(enemyId, wave, attackOrdinal) → 0..99
```

**옵트인 없이 기본 적용** `[확정 D-23]`. `DungeonProgressionConfig` 뒤에 두면
골든이 안 움직이지만 **기본 경로에서 잡몹이 여전히 똑같다** — 제보 ③이 해결되지
않고 해결한 척만 된다.

대가 2개를 안다:

- 던전 골든 12행이 움직인다. W1·W2와 같은 행이므로 **재고정 1회로 묶는다**(D-15).
- 기존 플레이어 체감 난이도가 바뀐다. Possessed가 기름을 빼앗으므로 **스킬
  사용 횟수가 준다.** 이번 사이클에서 난이도를 올리는 유일한 벡터다(피해 수치
  0개 증가 — 제약 2). 과하면 난이도 티어로 조절한다(AMENDMENT #11).

세피리아 대조: 난이도 13옵션 중 잡몹 **행동**을 바꾸는 것은 0개이고 패턴 강화는
보스 전용이다. **잡몹 행동 분화를 옵션 뒤에 두는 선례가 없다** — 넣는 곳은
전부 기본이거나 아예 없다.

| E10 | **모드 격리** | 프롤로그·아레나·시련 골든 바이트 동일 + 게이트 제거 변이가 깨짐 |

**E1과 E9가 짝이다.** E1은 궤적이 다름을 기계로 재고, E9는 사람이 그 차이를
읽을 수 있는지 본다. §4m 경고 — 정답과 오답이 같아지는 좌표계에서 재면
통과가 의미 없다. 궤적이 0.1픽셀 다른 것은 E1을 통과시키지만 E9를 통과하지
못한다.

**E10의 후반부가 핵심이다.** "안 움직였다"만 보이면 기능이 애초에 아무 데도
안 붙었어도 같은 결과가 나온다(§4q). 게이트를 없앴을 때 깨지지 않으면
게이트가 아니라 빈 코드다.
