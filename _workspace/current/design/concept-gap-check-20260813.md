# 컨셉 대조 — 로비와 스테이지 바닥이 "너무 단순하다" (2026-08-13)

사용자 지적: *"로비와 스테이지 바닥 플랫폼이 너무 단순하다, 그게 내 목표가 아니다.
컨셉에 맞는지 확인해야 한다."*

결론부터: **지적이 맞고, 이 저장소의 스펙이 이미 같은 말을 적어 두었다.**
`dungeon-interior-spec.md` §1.4가 그 진단을 문장으로 갖고 있다 —

> **요약: 지금 던전은 "아레나"이지 "던전"이 아니다.**

문제는 진단이 아니라 **그 스펙의 목표가 하나도 구현되지 않았다**는 것이다.

---

## 1. 스테이지 — 스펙 §2·§3이 미구현 [OBSERVED]

| 스펙이 요구한 것 | 코드의 현재 값 | 상태 |
|---|---|---|
| 플레이필드 half **735 × 390** (§2.1 안 A) | `ArenaHalfWidth = 520`, `ArenaHalfHeight = 270` (`SimTypes.cs:193`) | **미적용** |
| 면적 900,538 u² (2.04×) | 441,079 u² | **미적용** |
| `AddBoundaryWallRing` 신설 (§2.4) | 심볼 **0 hits** | **없음** |
| `AddOuterSilhouettes` 제거 | 2 hits, 살아 있음 | **미제거** |
| `AddZoneC` 제거 | 5 hits, 살아 있음 | **미제거** |
| `SilhouetteE` / `PlateBottomY` 제거 | 3 / 2 hits, 살아 있음 | **미제거** |
| 3레인 + 2스파인 그래머 (§3.2) | `EnvironmentBuilder`에 `Lane`·`Spine` **0 hits** | **뷰에 없음** |

**레인은 심에만 있고 뷰에는 없다.** `DungeonLayoutSpec.cs`가 `Lane`(4) `lane`(11)
`Spine`(7) `spine`(24)을 갖고 있는데 `EnvironmentBuilder`는 `lane`(7, 주석뿐)이고
`Spine`은 0이다. 즉 **심은 레인으로 막고 있는데 화면은 그 벽을 그리지 않는다.**
플레이어에게는 "왜 여기서 막히지"로 보이고, 시각적으로는 빈 타원 하나다.

§1.4의 리서치 대비 표(스펙 원문):

```
순환 레인 1~3개        →  레인 0 — 열린 타원
루프와 선택지          →  루프 0, 선택지 0 — 위상이 없어 결정할 게 없다
존 분할 + 존별 포컬     →  존 1개
엄폐물                 →  0~3개 (6 스테이지 중 3개는 블로커 0)
전투 정점 뒤 네거티브   →  전 영역이 네거티브라 대비가 없다
```

## 2. 로비 — 월드가 **평면 쿼드 2장**이다 [OBSERVED]

씬 베이크 렌더러를 전수로 셌다(`EnvironmentRendererProbeTests`):

```
CinderCourt.unity : MeshRenderer 2개
  CourtBackdrop   Universal Render Pipeline/Unlit   19.2 x 0.0 x 12.8   tex=cinder-court-backdrop
  VoidFloor       Universal Render Pipeline/Unlit   40.0 x 0.0 x 26.0   tex=abyss-chancel-stone
```

**둘 다 `Unlit`이고 둘 다 두께 0인 바닥 쿼드다.** 로비의 "공간"은 그림 한 장을
바닥에 깐 것이고, 그 위에 `LobbyStaging`이 얹는 것은:

```
워든 1 · 동료 1 · 보스 1 (원거리 'show' 루프)  +  포인트 라이트 1개
```

즉 **로비에 입체 지오메트리가 0개**다. 조명을 받는 표면도 0개다(Unlit이므로
`LobbyAccent` 포인트 라이트는 캐릭터에만 닿는다). 배경의 깊이감은 전부
`cinder-court-backdrop.png` 한 장이 그린 것이다.

worldview가 요구하는 것은 그림이 아니다:

> Cinder Court(잿불 법정)는 **기억의 감옥**이다. … 법정 관료제 어휘만 사용.
> 모든 해저드는 **법정 기능의 물화**(수문=말소, 방벽주=위증 보호 …)

**"법정"이라는 개념이 화면에 물리적으로 존재하지 않는다** — 법대도, 방청석도,
기둥도, 문도 없다. 캐릭터 셋이 그림 앞에 서 있다.

## 3. 왜 지금까지 안 보였는가

이번 사이클에 던전을 여러 번 손봤는데도 이게 안 잡힌 이유가 측정 가능하다.

- **텍스처 작업의 화면 점유율이 0.48%였다.** `env-stone`(0.27%) + `env-floor`(0.21%).
  스테이지 텍스처 18장을 재촬영해 품질을 크게 올렸지만 그 개선이 덮는 화면은
  1%에 못 미친다(`pale-ring-investigation.md`). 화면의 대부분은 지형 프리팹과
  배경 쿼드다.
- **법선 누락이 입체감을 통째로 지우고 있었다.** `bc799ee9`로 고치기 전까지
  절차 생성 메시 전부가 방향광을 못 받았다. 그래서 "단순함"이 **기하의 단순함인지
  조명의 부재인지 구분되지 않았다.** 지금은 구분된다 — 조명은 고쳤고, 남은
  단순함은 **진짜 기하의 단순함**이다.

## 4. 선택지 — 무엇부터 할지는 사용자 결정 [TARGET]

세 갈래가 있고 비용과 리스크가 다르다.

### A. 스펙 §2·§3을 그대로 구현 (설계 완료, 미구현)

이미 승인 대기 상태로 문서화돼 있다. 플레이필드 2.04배 확장 + 경계 벽 링 +
3레인 그래머. 스펙이 카메라 무변경(안 A)까지 계산해 뒀다.

- 비용: 심 상수 변경 → **골든 다이제스트 전면 재베이스**. 이 저장소에서 가장 비싼 축.
- 이득: "던전"이 되는 것. 사용자 요구의 정면 대응.
- 미결: 스펙 §2.3이 **안 A / 안 B 택일을 사용자에게 요청한 채로 멈춰 있다.**

### B. 로비를 입체로 (스테이지와 독립, 골든 무관)

로비는 심을 건드리지 않으므로 **골든이 움직이지 않는다**(§4e 순수 뷰 개정).
법정 어휘의 실제 지오메트리 — 법대·기둥 열·문 — 를 세우는 작업.

- 비용: 메시 생성(Higgsfield 3d 또는 키트 조합) + 배치. 심 변경 0.
- 이득: 첫 화면이 "그림 앞의 캐릭터 셋"에서 벗어난다.
- 리스크: 낮음. 되돌리기 쉽다.

### C. 둘 다 — B 먼저, A는 승인 뒤

B는 골든과 무관하고 A는 골든 재베이스를 요구하므로, **B를 먼저 하는 것이
직렬화 비용이 가장 낮다.**

## 5. 이 문서가 답하지 않는 것

- 새 지오메트리의 **아트 방향**(어떤 법정인가)은 정하지 않았다. worldview가
  어휘를 주지만 형태를 주지 않는다.
- 스펙 §2.3의 **안 A / 안 B 선택**은 여전히 사용자 결정이다.
- 성능 예산: 로비에 입체를 넣으면 WebGL 120 MB 예산과 드로우콜을 다시 재야 한다.
  현재 빌드 125 MB(data) — **이미 상한 근처다.**
