## 1. 조사가 확정 사항을 한 번 개선했다

deep-interview에서 사용자가 "최초 조우 자동 + 정지, 8회"를 확정했다.
서베이가 이의를 제기했다:

| | 장르 표본 | 우리 |
|---|---|---|
| 정지 총 횟수 | 중앙값 **0**, 확인 최댓값 **1** | 8 |
| 정지 사용 타이틀 | 19 중 **5 (26%)** | — |
| 배치 | 앞에 한 번 몰아넣음 (5 중 4) | 런 전반 분산 |
| 분산 선례 | **DD2 하나 — 표본 최다 혹평** | — |

**그런데 서베이의 결정적 발견은 횟수가 아니었다:**

> Returnal은 **무정지인데 과잉으로 혹평**받았고, Into the Breach는 **정지를
> 쓰는데 불만이 0**이다. 차이는 정지 여부가 아니라 **거절 가능성**이다.

사용자가 이 발견을 받아 "아무 키로 즉시 닫힘"을 추가했다. 8회는 유지하되
**관례 추종이 아니라 의도적 이탈로 기록**한다 (entry 13).

## 2. 2계층

정지 대상 선정 근거는 **G6 (0/7)** — 장르가 해저드 전용 안내를 안 하는 이유는

가시·산성처럼 시각으로 자명해서 Gungeon은 "환경 요소는 엔티티가 아니다"로
문서화를 명시 제외했다. **우리 6종은 다르다** — 방벽주가 적을 보호한다는 것,
재의 장벽이 주기적으로 밀려온다는 것은 외형으로 환원되지 않는다.

## 4. 수치가 심에서 온다

문안의 모든 숫자는 **상수를 보간**한다. 재입력하지 않는다.

```
"2.4초마다 뿜는다. 0.8초 전에 링이 뜬다 — 그때 나가라. 반경 90, 피해 8."
  ↑ VentPeriod   ↑ VentTelegraph              ↑ VentRadius ↑ VentDamage
```

밸런스가 바뀌면 레슨이 따라 움직인다. **심에서 어긋난 레슨은 없느니만 못하다.**

## 8. 결정론 — 정지가 골든을 안 건드리는 이유

`GameView.cs:79-84`가 명시한다:

> timeScale only stretches wall-clock per tick; tick size and input rules are
> unchanged.

명령 콘솔이 이미 `0.2f`로 이 경로를 검증했다. `0`은 정도의 차이다.

**단 하나 다른 것**: 0에서는 `Time.deltaTime == 0`이라 해제 애니메이션조차
안 돈다. 그래서 해제 폴링이 `MonoBehaviour.Update`(무스케일 벽시계)에서
돌고, `ResetRunUi`가 모든 종료 경로에서 카드를 뜯는다.

### 근본 원인이 설계 제약이 됐다

> 한 함수에서 만든 패널은 겹침 0. **두 곳 이상에서 만든 대역은 전부 겹침.**
> (예외 0건)

D2는 `Build()`가 라벨을, `EnableCampaignUi()`가 버튼을 만들어 생겼다.
**단일 빌더** — 정지 카드와 이탈 모달은 본체·라벨·버튼을 한 함수에서 만든다.
