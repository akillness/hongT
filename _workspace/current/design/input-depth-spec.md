# 키보드 조작 뎁스 설계 (2026-08-05)

사용자 요구: **"키보드 조작만으로 성장과 공격, 연계콤보 등 단순하지 않도록 키조작 방식을 뎁스있게"**

## 0. 현행 진단 [OBSERVED]

| 축 | 현재 | 문제 |
|---|---|---|
| 이동 | WASD/화살표 8방향 (`InputAdapter.cs:132-135`) | 정상 |
| 공격 | Space 1키 → 3타 고정 순환 (`CinderSim.cs:1413,1457`) | **선택지 0. 누르기만 하면 같은 순서** |
| 스킬 | Q/E/R/F 각 1키 (`SimInput` 필드 4개) | 1키=1스킬, 상호작용 없음 |
| 대시 | Shift 1키 | 회피 전용, 콤보와 무관 |
| 성장 | **완전 자동** (`GainXp`→`ApplyLevelStats`, `CinderSim.cs:999-1002`) | **레벨업에 플레이어 선택이 아예 없다** |

핵심: 키가 부족한 게 아니라 **같은 키가 문맥에 따라 다른 뜻을 갖지 않는다**.
키를 더 늘리면 외울 것만 늘고 뎁스는 안 생긴다. **문맥 = 방향 · 타이밍 · 상태**.

## 1. 설계 원칙

1. **새 키를 최소로 추가한다.** 뎁스는 키 개수가 아니라 조합에서 나온다.
2. **모든 조합은 기존 `SimInput.MoveX/MoveY`를 문맥으로 읽는다** — 이 필드는 이미
   공격과 같은 틱에 도착한다. 방향 파생 공격은 **계약 변경이 0**이다.
3. **각 뎁스 층은 몰라도 플레이가 되어야 한다.** Space 연타는 지금과 동일하게 작동한다.
4. **결정론 유지.** RNG 없음, 분기는 순수 산술.

## 2. 층 1 — 방향 피니셔 (계약 변경 없음)

3타 콤보의 **마지막 타**만 방향으로 갈라진다. 1·2타는 불변.

| 3타 시점 입력 | 피니셔 | 효과 |
|---|---|---|
| 방향 없음 (중립) | 기존 피니셔 | 현행 동작 그대로 |
| **바라보는 쪽** | **런처** | 넉백 ×1.6 — 되살린 `bighit` 클립이 여기서 진짜 쓰임 |
| **반대쪽** | **후퇴 베기** | 넉백 ×0.7, 플레이어가 뒤로 빠짐 — 포위 탈출 |
| **수직(위/아래)** | **회전 베기** | 넉백 ×1.0이지만 접촉 범위 ×1.35 — 다수 대응 |

- 읽는 값: 3타 발동 틱의 `MoveX/MoveY` 부호를 `_player.Facing`과 비교.
- 넉백은 이미 `HackSpec.ComboKnockbackDistance/Time`으로 존재 — 배율만 곱한다.
- **새 필드 0개, 새 키 0개.** 이동하면서 공격하던 사람은 자기도 모르게 이미 쓰고 있다.

## 3. 층 2 — 홀드 차지 (필드 1개 추가)

> **초안 폐기.** 처음엔 "탭(<0.25s) 대 홀드(≥0.25s)"로 갈랐는데, 그러면 View가
> 탭을 판정하려고 **키를 뗄 때까지(최대 250ms) 기다려야** 한다. 게임에서 가장
> 많이 눌리는 키에 250ms 지연을 붙이는 설계이므로 기각한다. 사용자가 고치라고
> 한 그 "조작감"을 정면으로 해친다.

**누르면 지금처럼 즉시 휘두른다. 계속 누르고 있으면 *다음* 타가 차지된다.**

| 입력 | 결과 |
|---|---|
| 누름 | **즉시** 콤보 스윙 — 현행과 완전 동일, 지연 0 |
| 스윙 액티브 창이 끝난 뒤에도 계속 누름 | 차지 시작 (게이지 표시) |
| 차지 0.45s 채운 뒤 릴리스 | **차지 강타**: 피해 ×1.8, 넉백 ×2.0 |
| 차지 중 릴리스 (미완성) | **아무 일도 없음 — 차지 폐기** |

- `SimInput.AttackHeld` — 눌린 동안 계속 true인 **평범한 지속 bool**. 엣지 판정
  불필요, 지연 없음.
- **초안 정정**: 초판은 미완성 릴리스를 "평범한 다음 콤보 타"로 적었다. 구현은
  그냥 폐기한다 — 손을 뗀다는 것은 취소한다는 뜻이지, 원하지 않은 스윙이
  튀어나오라는 뜻이 아니다. 차지에 실패해도 페널티는 이동 감속뿐이다.
- 차지 중 이동속도 ×0.45 — 위험을 감수하는 선택이 된다.
- 차지 완성 0.45s는 **보스 텔레그래프 0.80s보다 짧다** — 텔레그래프를 보고
  차지를 밀어넣을 시간이 있다. 두 수치가 서로를 읽는다.
- **연타하는 사람은 이 층의 존재를 모른 채 지금과 똑같이 논다.**

## 4. 층 3 — 대시 캔슬 (계약 변경 없음)

콤보 **후딜 중** Shift를 누르면 후딜을 잘라내고 즉시 회피한다.

- 창: 스윙 종료 후 `ComboLinkWindow`(0.9s) 안. 이미 존재하는 타이머다.
- 캔슬 시 콤보 인덱스는 **유지** — 회피 후 이어치기가 된다.
- 대시 쿨은 그대로 소모. 남발 불가.
- 이것이 "연계"의 실체: 공격→회피→공격이 하나의 흐름이 된다.

## 5. 층 4 — 성장 선택 (필드 1개 추가)

레벨업이 자동으로 스탯을 주는 대신, **3지선다를 띄우고 1/2/3 키로 고른다**.

| 키 | 선택 | 효과 |
|---|---|---|
| 1 | 공격 | 피해 +8% |
| 2 | 생명 | 최대 HP +6, 즉시 회복 |
| 3 | 민첩 | 이동 +4%, 대시 쿨 -6% |

- `SimInput.GrowthChoice` (0=없음, 1..3) 1개 추가.
- **선택 전까지 심은 계속 돈다** — 멈추지 않는다.
- **미선택 자동 확정은 5초**, 30초가 아니다. 30초로 두면 무시하는 플레이어가
  매 레벨 30초를 스탯 없이 보내는데, 보스전 전체가 19초다 — 즉 "손해 없음"이
  거짓이 된다. 5초면 현행(즉시 자동 분배)과 실질 차이가 없다.
- 자동 확정 값은 현행 `ApplyLevelStats` 분배와 **동일**하다. 무시하는 사람은
  지금 게임을 그대로 하는 것이고, 고르는 사람만 뎁스를 얻는다.
- **오퍼 대기 중 다음 레벨업이 도착하면**: 대기 중인 오퍼를 즉시 자동 확정하고
  새 오퍼로 교체한다. 큐를 쌓지 않는다 — 레벨 2개가 밀리면 어느 쪽을 고르는
  중인지 알 수 없어진다.
- 이것이 "성장을 키보드만으로"의 답이다.

## 7. 구현 현황 (2026-08-05 전량 반영 완료)

| 층 | 계약 영향 | 상태 |
|---|---|---|
| §2 방향 피니셔 | 없음 — `MoveX/MoveY` 재사용 | **반영** — `ResolveFinisherVariant`, 4분기 전부 테스트 고정 |
| §4 대시 캔슬 | 없음 — `_comboLink` 재사용 | **기존 동작** — `CastDash`가 이미 스윙을 취소하고 있었다 |
| §3 홀드 차지 | `SimInput.AttackHeld` +1 | **반영** — 0.45s 충전, 피해 ×1.8 / 넉백 ×2.0, 이동 ×0.45 |
| §5 성장 선택 | `SimInput.GrowthChoice` +1 · `IGrowthChoiceSnapshot` | **반영** — 5초 자동 확정, 1/2/3 |

### 계약 처리 방식

`SimInput`에 필드 2개를 추가했다(`AttackHeld`, `GrowthChoice`). 둘 다 기본값이
`false`/`0`이라 **아레나·캠페인 경로는 바이트 단위로 불변**이며, 모든 신규 로직은
`_dungeon` 게이트 뒤에 있다.

오퍼 노출은 **`IHackSnapshot`을 건드리지 않았다** — `RunPreparationSnapshot.cs`가
같은 이유로 만들어 둔 선례를 따라 `IGrowthChoiceSnapshot`을 별도 추가했다.

### 초안에서 바뀐 것

- **§3 릴리스 처리**: 미완성 차지는 "다음 콤보 타"가 아니라 **폐기**한다(§3 주석).
- **§5 민첩**: 이동속도만이 아니라 **대시 쿨 −6%/pt**(하한 ×0.55)도 준다. 속도만
  주면 민첩이 셋 중 명백히 약한 선택이 되어, 실제로는 2지선다가 된다.
- **§5 자동 확정 30초 → 5초**: 보스전 전체가 19초인데 30초를 무스탯으로 보내면
  "무시해도 손해 없다"가 거짓이 된다.

### 검증

EditMode 224/224. 신규 5건: 무시 시 무손실·자동 확정, 오퍼 중 심 미정지(오퍼
시계를 증인으로 사용 — 위조 불가능한 단조 감소), 3축 실효성, 차지 창이 보스
텔레그래프 안에 들어감, 연타 파일럿의 차지 누적 0.

## 8. 검증 계약

- 방향 피니셔 4분기 전부 EditMode로 고정 (넉백 거리로 판정).
- 대시 캔슬: 후딜 중 캔슬 시 콤보 인덱스 보존 확인.
- **현행 동작 보존 증명**: 방향 없이 Space만 연타하는 파일럿의 Digest가
  변경 전과 **바이트 동일**해야 한다. 기존 파일럿 테스트가 이걸 이미 한다.
- 아레나 경로 불변 — 전부 `_dungeon` 게이트 뒤.
