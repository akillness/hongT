# §S1 스킬 실루엣 VFX — 실기 프레임 비용 측정

run-id 20260806-skill-vfx · View 레인 · `[OBSERVED]` 전부 실측
방법: WebGL 빌드 → 로컬 서빙 → Chromium 실행, WebGL 컨텍스트의 draw 계열
함수를 래핑해 프레임당 draw call 계수 + `requestAnimationFrame` 델타 샘플링.
CPU 스로틀은 CDP `Emulation.setCPUThrottlingRate`.

---

## 0. 왜 이 문서가 있는가

인계 시점(`skill-vfx-mode-coverage.md`)에 미검증으로 남긴 항목:

> 동시 shard 18개는 각자 머티리얼을 가져 VFX 오버레이 draw call 가이드
> (10 미만)를 초과한다. 기존 풀 38슬롯과 일관되나 실기 측정 전까지
> `[TARGET]`이 아닌 미검증으로 둔다.

에디터 점유가 풀려 측정 가능해졌으므로 닫는다. **결론: 우려의 전제는 맞았고
(초과한다) 결론은 틀렸다(비용이 없다).**

## 1. Draw call — 우려는 사실이었다

| 상태 | median | max |
|---|---|---|
| 아레나 유휴 | 44 | 45 |
| 아레나 노바 발동 | 65 | 65 |
| **던전 유휴** | **146** | 147 |
| **던전 전 스킬 중첩**(E 크라운 10 + Q 팬 4 + F 껍질 8) | **175** | **182** |

스킬 발동이 더하는 draw call: 아레나 **+21**, 던전 **+29 ~ +35**.

`game-vfx` 스킬의 "VFX 오버레이 draw call 10 미만" 지침은 **초과한다**.
다만 그 지침은 오버레이 단독 예산이고, 이 프로젝트의 던전 프레임은 이미
146 baseline이다. 스킬 VFX는 그 위 약 20~24%다.

**측정 무효 사례 기록**: 첫 시도에서 idle/nova 모두 42로 평평해 "shard는
공짜"로 읽힐 뻔했다. 스크린샷을 찍어보니 체력 0 게임오버 화면이었고 아무것도
발동하지 않았다. 이후 모든 측정은 **점수·적 수·피해 숫자 변화로 발동을 먼저
증명한 뒤** 채택했다. 평평한 그래프는 "비용 없음"과 "아무 일도 없음"을
구분하지 못한다.

## 2. 프레임 시간 — 노이즈 바닥 아래

| CPU 스로틀 | 유휴 median | 스킬 중첩 median | 델타 |
|---|---|---|---|
| 1x | 8.3 ms | 8.3 ms | 0 |
| 4x | 8.3 ms | 8.3 ms | 0 |
| 6x | 8.5 ms | 8.5 ms | 0 |
| 10x | 17.4 ms (57 fps) | 16.8 ms (60 fps) | -0.6 (노이즈) |
| 20x | 49.8 ms (20 fps) | 42.4 ms (24 fps) | -7.4 (노이즈) |

1x~6x 구간의 8.3 ms는 **120 Hz vsync 상한**이라 실비용을 가린다. 10x/20x에서
vsync를 넘겨야 실제 프레임이 드러나고, 거기서도 스킬 중첩 쪽이 오히려 빠르게
측정된다 — 실제 이득이 아니라 **shard 비용이 측정 분산보다 작다**는 뜻이다.
20 fps까지 떨어뜨려도 shard는 프레임에 보이지 않는다.

## 3. 여전히 측정 안 된 것

- **GPU fill rate**. CDP 스로틀은 CPU(메인 스레드)만 늦춘다. draw call
  오버헤드는 대부분 CPU 드라이버 비용이라 위 측정이 유효하지만, 2015년급
  모바일 GPU의 fill rate는 재현하지 않았다.
  다만 shard는 `widthMultiplier` 0.05의 가는 선이라 overdraw 기여는 이미
  출하 중인 scorch quad·파티클 스프라이트보다 작다. `[INFERENCE]`
- **실제 모바일 기기**. 이 측정은 M5 Pro / 헤드리스 Chromium이다.
  20x 스로틀은 약한 CPU의 근사이지 기기 검증이 아니다.

## 4. 판정

| 항목 | 인계 시점 | 측정 후 |
|---|---|---|
| draw call이 오버레이 지침을 넘는가 | 미검증 | **넘는다** (+29~35) |
| 그것이 프레임 비용인가 | 미검증 | **아니다** (20x에서도 노이즈 이하) |
| 실루엣이 화면에 나오는가 | 미검증 | **나온다** (융기 크라운·크랙 팬 육안 확인) |
| 게이지가 줄어드는가 | 미검증 | **줄어든다** (135→128→37→0 렌더 확인) |

최적화 작업은 **불필요**하다. 재측정이 필요한 시점은 실제 저사양 기기가
확보되었을 때, 또는 shard 폭·개수를 키우는 변경이 들어올 때다.
