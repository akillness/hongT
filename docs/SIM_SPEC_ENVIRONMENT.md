## §E0. 문제 정의 (측정된 사실)

- 전투 판정면: 캠페인/던전 전 스테이지가 `GameMode.Dungeon` 경로
  (`GameDirector.StartDungeon` → `HackConfig.TryDungeon` → `_dungeon=true`)로
  **타원 클램프**를 쓴다 (`CinderSim.ClampToArena`, half 520×270, 중심 768,604).
  다이아몬드(L1)는 Arena(동결 회귀 게이트)와 Prologue 둘뿐.
- 드레싱 평면은 바운딩 박스(1040×540 = 561,600 u²) 그대로인데, 클램프는
  마진 차감 후 반경으로 자른다(`ClampToArena`: halfW−margin, halfH−margin/2).
  **플레이어 보행 타원 = 486×253 (margin 34) = π·486·253 ≈ 386,290 u² —
  바운딩 박스의 68.8%.** 즉 그려진 바닥의 **31.2%가 못 걷는 면**이다
  (적 도달 타원은 496×258 ≈ 402,024 u², 71.6%). AMENDMENT #4의 "+57% 도달"은 마진
  미차감 raw 타원 기준 — 환경 설계는 마진 차감 값이 진실이다.
- 카메라(pitch 55°, FOV 42, 거리 20/24.5 + aspect 보정) 프레임에 "구멍"은
  없다 — SceneBuilder가 이미 `VoidFloor`(40×26 u 언릿 쿼드, y −0.35, 근흑색)를
  깔아 프러스텀 지면을 전부 덮는다. **문제는 구멍이 아니라 그 쿼드가
  "아무것도 아닌 것"으로 읽힌다는 것** — 프레임의 상당 비율이 환경이 아닌
  VoidFloor 맨살이다. 외곽 안개 밴드(FogStartOffset 2, FogEndOffset 5.5)는
  원경만 가린다. 따라서 게이트는 레이캐스트 적중("맞는가")이 아니라
  **커버리지 비율("무엇에 맞는가")**이어야 한다 (§E8).
- 지형 프리팹은 3종(cinder-span/abyss-chancel/echo-throne)뿐이고 9개 논리
  스테이지가 이를 재사용, 드레싱은 스테이지당 9-10개 정적 배치.

## §E0.5 구조 선택 — 고정 카메라 유지 (A) vs 팔로우 카메라 + 다중 방 (B)

던전 카메라는 **고정 궤도**다: `CameraRig` 던전 프로필은 focus=ArenaCenter
고정, pitch 55°, 거리 20/24.5 — 플레이어를 따라가지 않는다(예외: 보스 인트로
포커스 펄스뿐). 거리 20에서 프레임 높이 ≈ 2·20·tan(21°) ≈ 15.4 u인데 도달
타원은 10.4×5.4 u — **빈 여백의 산술적 원인은 타일 부족이 아니라 프레임이
플레이 영역보다 큰 것**이다. 이 사실이 두 갈래를 만든다:

| | A. 고정 카메라 + 단일 방을 채운다 (본 개정) | B. 팔로우 카메라 + 다중 방·복도 |
|---|---|---|
| 카메라 | 불변 (거리·FOV 유지 — 캐릭터 축소 결정 보존) | 팔로우 전환 + 텔레그래프 가독성·군중 티어·안개 밴드 전면 재튜닝 |
| 심 | **0 변경** (View 전용) | 클램프 기하 재설계(복도·방 다각형), 스폰 슬롯 8방위 재설계, 웨이브 계약 개정 |
| 골든 | 전 행 불변 | 전 행 재기록 |
| 정체성 | "고정 시간표 암기" 유지 | 탐험형으로 피벗 — 기믹 타임라인 서사 재정의 필요 |
| 규모 | 이번 사이클 | S8급 AMENDMENT 다수 + 자산 배치 |

**판정: A 채택.** 오퍼레이터 요구 2건("카메라 빈공간 없음", "던전 내 모든
공간 이동·전투")은 A로 충족된다 — 프레임을 환경(Zone B/C + 안개)으로 채우고,
바닥으로 읽히는 모든 면을 타원 내접으로 제한하면 보이는 바닥 전부가 전투
가능 공간이 된다. 유저 레퍼런스의 "시작점→전투방→보스방 복도 연결" 문법은
단일 방 안에서 **랜드마크 문법**(입구 게이트→전투 바닥→보스 게이트 동선,
§E3)으로 번역해 이행한다. B는 §E9 후속 후보 ②의 확장으로 기록 — B를
택하더라도 본 개정의 타일 킷·결정론 배치기가 방 단위 재료로 그대로 쓰인다.

## §E1. 원칙 (위반 금지)

1. **심 불변.** 이 개정의 모든 산출물은 `Assets/Scripts/View/` + 에셋이다.
   `CinderCourt.Sim`은 1바이트도 바뀌지 않는다. 골든 전 행 무이동이 증명.
2. **보이는 바닥 = 걸을 수 있는 바닥.** "바닥으로 읽히는" 표면은 타원 내접
   영역에만 존재한다. 타원 밖은 벽·낭떠러지·수몰 수로·상층 갤러리 등
   **명백히 비보행 문법**으로만 채운다. (모서리 21.5% 문제의 해법은 노름
   확장이 아니라 모서리를 바닥이 아닌 것으로 만드는 것이다.)
3. **클램프 노름 불가침.** 타원/다이아몬드 판정식은 손대지 않는다. 노름
   확장은 별도 AMENDMENT + 골든 재기록 사안이다.
4. **결정론.** 절차 배치는 전부 정수 해시(FNV-1a 스타일, 기존
   `PreparationHash` 문법) 시드 → 같은 스테이지는 부팅마다 바이트 동일한
   환경. `System.Random`·`UnityEngine.Random` 금지. EditMode 테스트가 고정.
5. **프레임 무보이드.** 던전 카메라의 지면 교차 사각형(최대 거리 24.5,
   와이드 aspect 보정 포함)은 [환경 지오메트리 ∪ 안개 밴드]에 완전히
   덮인다. 분석적 검증이 아니라 **EditMode 카메라 레이캐스트 테스트**로 고정.
6. **WebGL 예산.** compute/threads 금지, 신규 텍스처 ≤1024, 총 빌드 증가
   ≤8 MB. 런타임 생성 지오메트리는 스테이지 진입 시 1회 빌드 후
   `StaticBatchingUtility.Combine` — 프레임 루프 할당 0 유지.

## §E2. 모듈러 타일 킷 (그리드 128 sim-px = 1.28 u)

킷은 **코드 생성 프리미티브 + 기존 라이브러리 자식 재사용**으로 구성한다
(신규 외부 에셋 없음 — 자산 도구 계약은 CLAUDE.md §3, 필요 시 후속 배치).

| 모듈 | 규격 (sim-px) | 용도 | 소스 |
|---|---|---|---|
| FloorTile | 128×128 | Zone A 바닥 패널 (틈새 메꿈·플레이트 위 유광 패널) | 코드 쿼드 + 지형 머티리얼 |
| WallSegment | 128×h96 | Zone B 링 벽 1칸 | 코드 박스 |
| WallPillar | 48×h128 | 링 벽 이음 기둥 (16칸마다) | 라이브러리 feature 클론 |
| GateArch | 256×h160 | 입구(하단)·보스 게이트(상단) 랜드마크 | 코드 박스 조합 + 엠버 발광 |
| GalleryDeck | 256×128, y+80 | Zone C 상층 회랑 (비보행 — 난간 포함) | 코드 박스 |
| BrokenBridge | 384×64, y+110 | Zone C 끊어진 다리 (입체감 실루엣) | 코드 박스 2분절 |
| SunkenChannel | 256×128, y−50 | Zone C 수몰 수로 (sluice 계열) | 코드 쿼드, 저면 |
| TorchPost | 32×h96 | 조명 앵커 (§E6) | 라이브러리 prop 클론 + 발광 |

- 배치 좌표는 전부 **sim 좌표**로 기록하고 `ViewWorld.ToWorld`로만 변환한다
  (Scale 0.01 — 기존 드레싱 계약과 동일).
- 콜라이더 금지 (`ViewColliderStripConventionTests` 계약 유지). 이동 차단은
  심 클램프가 유일한 진실이다 — 벽은 클램프 경계의 **시각화**일 뿐이다.

## §E3. 링 아키텍처 (Zone A/B/C)

타원 매개변수 `e(x,y) = √((x−768)²/520² + (y−604)²/270²)` 기준. 경계는
리터럴이 아니라 **마진 상수에서 유도**한다 (상수가 바뀌면 링도 따라간다):

- `eEnemy`: 클램프가 x는 `halfW−margin`, y는 `halfH−margin·0.5`를 쓰므로
  정지선은 축마다 다르다 — x축 496/520 = 0.9538, y축 258/270 = 0.9556.
  **구현은 보수적으로 min = 0.9538 하나를 쓴다** (FloorTile이 정지선을 절대
  못 넘고, 벽은 y축에서만 0.5px 안쪽 — 무해). 상수는 `SimConfig` 마진에서 유도.
- `ePlayer = (520 − PlayerMarginClamp 34)/520 = 0.935` — 플레이어 정지선.

| Zone | e 범위 | 내용 | 문법 |
|---|---|---|---|
| **A 전투 바닥** | ≤ eEnemy (0.954) | FloorTile 패널 + 심 기믹(분출구/기둥/제단…) | 완전 개방 — 심 해저드 외 시각 장애물 배치 금지. 적은 벽에 붙고(0.954) 플레이어는 2% 안쪽(0.935)에서 멈춘다 — "적이 벽에 몰린다"로 읽히는 올바른 결과 |
| **B 경계 벽 링** | eEnemy – eEnemy+0.14 | WallSegment/WallPillar 타원 궤도 배치, 입구·보스 GateArch 2개소 | 클램프가 멈추는 정확히 그 선에 벽이 서 있다 — "여기까지"가 시각적으로 자명. 정지선보다 바깥에 벽을 세우면 "벽에 닿기 전에 멈추는" 이물감이 남는다 (금지) |
| **C 외곽 입체** | > eEnemy+0.14, 프러스텀 끝까지 | GalleryDeck(+80)·BrokenBridge(+110)·SunkenChannel(−50)·기존 드레싱 | 높이가 다르므로 바닥으로 오독 불가. 안개 밴드와 겹치며 소멸 |

- **모서리 규칙**: 바운딩 박스 모서리(e>1)는 FloorTile 금지. Zone B 벽
  뒤편 + Zone C 구조물로만 채운다. → 원칙 2 충족.
- **랜드마크 동선**: 입구 GateArch = 하단 (768, ~890 링 교점), 보스 GateArch
  = 상단 (768, ~320 링 교점) — 플레이어 스타트(768,646)와 스폰 슬롯 8방위의
  기존 사실을 서사화한다. 퍼즐 구역 = 제단/방벽주 alcove (Zone B 벽을
  국소 후퇴시켜 기믹 좌표를 벽감으로 감싼다 — 기믹 반경 + 50px 클리어런스).
- **프롤로그/아레나 예외**: 다이아몬드 클램프 모드는 이 개정 범위 밖 —
  기존 맨 코트 유지. (타원 링을 다이아몬드에 재사용하면 미스매치가
  50%로 커진다. 별도 개정 후보로만 기록.)
- **훈련장(시련) 예외 — 명시적 범위 밖 (2026-08-07)**: 시련은 던전 카메라
  (55° 고정 궤도)를 쓰지만 stageId가 `TrainingTrials` 소속이라 캠페인 앵커
  팔레트가 해소되지 않는다 — 이번 개정은 `SetStageEnvironment(null)`로
  맨 코트를 유지한다. 시련 프레임의 VoidFloor 노출은 알려진 상태다.
  후속 후보(§E9 ⑤): 시련의 지배 기믹을 §E4 팔레트로 매핑해 환경 부여.

## §E5. 결정론 절차 배치

- 시드: `seed = FNV1a(stageId) ^ (moduleKind * 0x9E3779B9)` — 부팅·세션 무관.
- Zone B: 타원 둘레를 등호(arc-length) 분할해 벽 칸 수 N ≈ 둘레/128px.
  칸별 요철(±6px 반경 방향, 시드 하위비트)로 수제작 느낌. GateArch 2개소는
  고정 교점 — 절차 대상 아님(랜드마크는 수동 앵커, 복도식 연결 원칙).
- Zone C: 팔레트별 후보 슬롯 테이블(정적) × 시드 셔플(Fisher-Yates, 해시
  스트림) → 배치 8–14개. 회전은 90° 스냅 ± 시드 지터 ≤12°.
- **BSP/WFC 불채택 판정**: 단일 아레나(방 1개) 구조라 방 분할 알고리즘의
  적용 대상이 없다. 절차성은 Zone B 요철 + Zone C 슬롯 셔플로 한정 —
  이것이 이 게임의 "고정 시간표 암기" 정체성과도 정합한다(레이아웃도
  스테이지별 고정, 판마다 동일). 다층 던전 도입 시 재평가.

## §E6. 조명·분위기 (WebGL 예산 내)

- 실시간 포인트 라이트 ≤ **4** (URP Forward, WebGL): 입구/보스 게이트 2 +
  스테이지 악센트 2 (TorchPost 앵커 중 시드 선정). 나머지 횃불은
  **엠버 발광 머티리얼**(unlit emissive 클론 — 기존 seed 머티리얼 문법)로
  라이트 없이 빛나 보이게.
- 그림자: 실시간 그림자 캐스터 0 유지(현행). 입체감은 higher/lower Y +
  발광 대비로 만든다.
- 안개 밴드(FogStartOffset 2 / FogEndOffset 5.5)는 Zone C 소멸 경계로
  유지 — 프러스텀 무보이드 증명의 합집합 항이다.

## §E7. 성능·컬링

- 오클루전 컬링: **불채택 판정** — 탑다운 55° 카메라는 가림 관계가 거의
  없고, 런타임 생성 메시는 베이크 대상이 아니다. 대체 수단:
  (a) 스테이지 진입 1회 빌드 후 `StaticBatchingUtility.Combine(root)`,
  (b) 머티리얼 공유(지형 3종 + seed 클론 ≤6종)로 드로우콜 상한,
  (c) 프러스텀 컬링(기본) + 안개 소멸.
- 예산 게이트: 환경 루트 정점 ≤ **60k**, 드로우콜(배칭 후) ≤ **40**,
  스테이지 진입 빌드 시간 ≤ **50 ms** (에디터 측정 기준, 배포 전 실측 기록).
- 프레임 루프 할당 0 — 빌드는 진입 1회, 갱신 없음.
